## Current flows

The source route index is [`internal/web/ROUTES.md`](../../../internal/web/ROUTES.md); actual handlers and `cmd/server/main.go` take precedence over its aspirational expansion list.

| Flow | Current entry, behavior and exit | Persistence and limits | Evidence |
| --- | --- | --- | --- |
| Guest builder | `/decks/new` offers Commander, Standard and Sandbox, plus import and resumable draft entry. Workbench supports search/add, quantities, main/side/maybe, printing choices and naming. Login carries a local `next` URL with `save_guest=1`. | Browser-local draft; signing in alone is not continuous account autosave. New/reset flow can replace the relevant draft slot. | Browser start screen, Forest add and reload; `decks_create_list.go`, `deck_show_guest_draft_script.html.tmpl`. |
| Commander | `/decks/new/commander/` offers searchable eligible cards and randomized popular batches. POST `/decks/new/commander` revalidates selection, then redirects both guests and signed-in users to a reset local workbench with commander name and printing ID. Editor can choose a commander from eligible deck cards; saved path POSTs `/decks/commander`. Empty Commander deck can request Quick Build. | One commander name/printing field; card eligibility is catalog-based. No two-commander representation or Forge legality guarantee. Quick Build is a starter recommendation, not an engine-validated match. | Browser Kaalia search → selection → commander panel and printing query; existing creation/printing tests; handler source. |
| Sandbox | `/decks/new/sandbox` redirects to `/decks/new/workbench?format=Sandbox&sandbox=1`. No commander or deck-size restrictions. Standard uses the common workbench with its own format. | Sandbox uses a separate draft slot from the common format draft. | Browser one-Forest sandbox, reload, Analysis, goldfish round trip. |
| Import | `/decks/import` accepts pasted text or TXT/CSV file contents. POST parses boards, names, quantities and optional print identity, resolves the local catalog, and seeds the workbench. Direct import can omit unresolved/problem rows with warnings/description notes. Save-to-account requires resolution rather than silently persisting unresolved cards. | Imports become local drafts first. Existing parser supports text/CSV metadata and board/printing preservation; does not supply a general merge-into-open-editor interface. | Browser `M0 Import Fixture`: Standard, 4 Forest main, 1 Mountain side, 1 Island maybe → visible 4/1/1; parser/import tests. File chooser itself not exercised. |
| Account and save | Signup/login establish a session. `/decks` lists owned saved decks. Local workbench “Save deck” or auth-return invokes POST `/decks/import/save`; successful response must contain a deck ID before redirect. `/decks/{id}` is the owned saved editor. Card/printing/name operations POST and refresh workspace JSON; notes/tags/format use debounced overview mutations. | PostgreSQL owns account/deck/card/board data. Draft-to-account import is transactional. Saved-editor state is held in memory, distinct from guest local storage. Failure and concurrent-save guarantees require BUG-064B triage, not an assumed autosave promise. | Account/import atomicity and ownership tests plus source inspection; [Signed-in/failure observations](V2-002.md) extend this baseline. |
| Publish and public decks | Saved editor menu toggles public state through `/decks/settings`. `/decks/public` browses filters/sort/pages; `/decks/public/{slug}` shows the public deck, owner link, card/board information, prices, sample hand and copy/export. Non-owner can fork through `/decks/public/fork` after login; owner can return to edit. | Explicit public flag/slug, persisted in DB. Fork is a separate owned copy. CPU launch must not imply publication. Deck likes/comments/popularity signals are not established by existing card-print favorites. | `decks_public.go`, `decks/public.go`, public template/data/query tests; V2-002 additionally exercised synthetic local publish/browse/detail/unpublish. No public-site publication. |
| Analysis | Workbench Analysis shows counts, mana curve/profile, category guides, sample hand, notes/tags and format-aware warnings. `/decks/analytics` computes from owned saved data or posted workbench input. | Derived output, not durable match state or authoritative game legality. Selected print metadata affects presentation/prices. | Browser Forest: 1 card/land and green source; analytics tests cover Commander/constructed/limited warnings and commander exclusion. |
| Goldfish | Saved `/decks/playtest/{id}` loads owned DB rows; local draft POST `/decks/new/playtest` carries a snapshot. Both render `deck_playtest.html.tmpl` and `assets/playtest.js`. Opening hand, mulligan/keep, manual zones/turn/life/mana/tools; Game → Back to Deckbuilder returns to the editor. | Gameplay state is ephemeral browser memory. Workbench seed is preserved separately via local storage and a session-storage `.playtestReturn` entry on return/pagehide. It preserves deck data, not a resumable rules-engine match. Side/maybe data stays in the draft seed while playable rows come from main. | Browser one-Forest sandbox → free mulligan → Keep (turn 1, life 20) → Game → Back; same draft name and 1 Forest. Payload/printing/format tests; no full-game rules claim. |

Source files in the table without a directory prefix are under `internal/web/` (templates under `internal/web/templates/`).
