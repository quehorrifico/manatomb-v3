# V2-020 — concrete session/deck contract

Review checkpoint, September 18, 2026. Branch `codex/v2-release-candidate`; baseline HEAD `0ab74245912407e98f2cb5131a431a67cfed0f1f`. Owner conditionally accepted G1 for local implementation; no hosted gate, release, merge or expenditure is accepted.

The concrete types are `internal/forge/contract.go`. The private protocol is `manatomb-forge/v1`, using the same Forge pin as V2-010. A session has a supervisor UUID and a separate engine incarnation. An action binds both the URL session and the engine's `session`, `revision`, `prompt`, `request`. The trusted Go web process supplies the signed-in numeric owner; browsers cannot choose an owner or a viewer. Only the human viewer is projected.

Decks contain `name`, `commanders:[{name,quantity}]`, and `main:[{name,quantity}]`. Transport validation rejects invalid counts, repeated entry names, control/section injection and totals other than 100. Forge resolves actual catalog cards and performs Commander conformance. Unknown cards produce an error rather than disappearing. A saved ManaTomb deck still has one persisted commander; CPU setup supports a second commander explicitly without rewriting the editor schema. Actual pinned-Forge regressions accept **Tymna + Thrasios** and **Wilson + Raised by Giants** with 98 basic lands, retaining both commander entries. Printing metadata is intentionally not a gameplay input: Forge chooses its pinned catalog printing/rules. No custom scripts, URLs or card implementations are accepted.

Actions use `ok`, `cancel`, `card`, `player`, or `reply`. Reply selections are integer option indices, including explicit `[]` for optional choices/reveal acknowledgment. Scalar/amount/text prompts carry their explicit value field and are checked against the outstanding Forge prompt. A first integration attempt uncovered an omitted empty array during Go serialization; the correction and `TestEmptyReplySelectionSurvivesTransport` preserve it.

Examples:

- Valid: `POST /api/cpu/sessions/{id}/actions` with `{"request":"unique-command","session":"engine-incarnation","revision":12,"prompt":"current-prompt","action":"reply","selected":[1]}`.
- Stale prompt or competing distinct reply: HTTP 409; the consumed input cannot be applied twice.
- Same command/payload: bounded receipt (128 entries) returns the known response. Changed payload with that command ID: 409. Evicted receipts cannot replay an old prompt because revision/prompt identity still fails.
- Uncertain acknowledgment: reconnect/read before retry; same command may be retried while its receipt remains. ACK means admission, not spell resolution. No crash-proof exactly-once or replay claim.
- Other user's session: 404. Unauthenticated browser: 401. Invalid mutation Origin: 403. Disabled/missing/unavailable engine: 503; ordinary site routes are independent.
- Unknown Forge card: startup fails with a deck-validation error; worker is reaped. Capacity is reserved during validation to bound concurrent catalog loads, not held after failure.
- Terminal: `finished` is Forge's natural outcome; `cancelled`, `expired`, `failed` are infrastructure/session outcomes, not fabricated losses.
